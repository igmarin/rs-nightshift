# Decision log

Architecture and product decisions, recorded so future-you (and future agents)
know why things are the way they are.

## ADR-001: Binary-only release, no crates.io publish

**Date:** 2026-08-14 (phase-3)

**Context:** The crate exposes everything publicly (no `pub(crate)` gating).
Publishing to crates.io would expose the full internal API on docs.rs, including
test helpers, internal error variants, and trait implementations that aren't
meant for external consumption.

**Decision:** Ship prebuilt binaries via cargo-dist's shell installer. Set
`publish-jobs = []` in `dist-workspace.toml`. Do not publish to crates.io for
0.1.0.

**Consequences:**
- Users install via `curl | sh` — no Rust toolchain required on the target server.
- `cargo install rs-nightshift` does not work (by design).
- The crates.io track (#30-#35) is parked until the public API surface is
  curated (#32). When unparked, both install methods can coexist.

## ADR-002: curl installer as the primary install method

**Date:** 2026-08-14 (phase-3)

**Context:** The target audience is server operators who set up Ollama + models
on a Linux box. They typically do not have the Rust toolchain installed, and
installing it just to get a CLI binary is unnecessary friction.

**Decision:** Use cargo-dist's generated `rs-nightshift-installer.sh` as the
primary install method. The script downloads the right tarball for the host
triple, verifies the SHA256 checksum, and installs the binary to
`$CARGO_HOME/bin`.

**Consequences:**
- One command, no prerequisites.
- Checksum verification is built in.
- The installer is generated by cargo-dist and committed to the repo, so it's
  auditable and version-pinned.

## ADR-003: Split doctor.rs and artifacts.rs into submodules

**Date:** 2026-08-16 (issues #48, #49)

**Context:** graphify analysis showed `doctor.rs` and `artifacts.rs` as
mixed-concern monoliths with low cohesion. `run()` had degree 72 (god node),
and `Error` bridged 12 communities partly because of the monolithic structure.

**Decision:** Split `doctor.rs` into `doctor/{mod,catalog,host,report}.rs` and
`artifacts.rs` into `artifacts/{mod,state,qa,util}.rs`.

**Consequences (measured by graphify re-run):**
- `run()` degree dropped from 72 to 36 (50% reduction).
- Community count went from 23 to 32 (more focused modules).
- `Error` dropped off the top-10 god nodes.
- No behavior change — all 123 tests still pass.

## ADR-004: CI drift-detection test

**Date:** 2026-08-16 (issue #50)

**Context:** `ci.yml` and `release-checks.yml` must run the same quality gates.
Without a test, a gate added to `ci.yml` but not `release-checks.yml` would be
silently missing from the release path.

**Decision:** Added `tests/workflow_consistency.rs` that parses both YAML files
and asserts `release-checks.yml` runs a superset of `ci.yml`'s quality gates.
The test uses exact command matching (not substring) to avoid false positives.

**Consequences:**
- Found real drift on first review: `cargo test --doc` was in `ci.yml` but not
  `release-checks.yml` (fixed in #59).
- Any future gate addition to `ci.yml` must also be added to
  `release-checks.yml` and to `REQUIRED_GATES` in the test.

## ADR-005: Error enum as a single crate-wide type

**Date:** 2026-08-16 (issue #52, tracking)

**Context:** The `Error` enum has 10 variants and 73 callers across 15 files.
graphify shows it bridging 12 communities with betweenness 0.409 — the highest
of any node.

**Decision:** Keep the single enum for 0.1.0. Do not split into module-local
error types. Track this in #52 for post-0.2.0 review.

**Rationale:** Every caller uses `?` propagation, not match-on-variant. The high
betweenness is the natural consequence of a shared error type in a single crate
— it's the error-propagation spine, not a god object. Splitting would add
indirection (conversion boilerplate) without benefit at this scale. The only
variant that could benefit from being more specific is `Artifact(String)`, which
is used as a catch-all in ~6 places in `pipeline.rs` and `artifacts/mod.rs`.

**Trigger for revisiting:** If the `Artifact(String)` catch-all starts producing
ambiguous error messages during real beta runs (#36), promote #52 to 0.2.0 and
introduce specific variants.

## ADR-006: Config-driven role graph replaces the fixed pipeline

**Date:** 2026-08-19

**Context:** The fixed five-stage pipeline (PM → TechLead → Dev → QA → Writer)
with a hardcoded `Role` enum is too rigid to validate against real models and
cannot express arbitrary role compositions (Product Owner / Developer / QA, or
Researcher / Writer / Editor). The operator wants to leave a task overnight and
review a report in the morning, with per-role control over provider, model, and
model-specific options (think/reasoning, temperature).

**Decision:** Replace the hardcoded pipeline with a config-driven **role graph**.
Roles are declared in `nightshift.toml` (provider, model, options, prompt,
output, routing). The harness routes on a small deterministic verdict vocabulary
(`continue`/`issues`/`questions`/`done`/`fail`). See `docs/role-graph.md`.

**Consequences:**
- The `Role` enum and the hardcoded `run()` orchestration are retired.
- Reusable primitives (test detection, `git apply`, context gather, error
  mapping, unload) become code-side capabilities, preserving INV-1..INV-11.
- Beta scope: linear chain + loop-backs; providers Ollama, Deepseek,
  Kimi/Moonshot; env-var auth.
- crates.io stays out (ADR-001 reaffirmed); Cline is deferred post-beta.
