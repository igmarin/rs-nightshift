# Releasing

Releases are built by [`.github/workflows/release.yml`](../.github/workflows/release.yml),
generated by [cargo-dist](https://opensource.axo.dev/cargo-dist/). Config lives
in [`dist-workspace.toml`](../dist-workspace.toml).

## Cut a release

1. Bump `version` in `Cargo.toml` (and `Cargo.lock`), merge to `main`.
2. Move `[Unreleased]` entries in `CHANGELOG.md` into a new version section.
   `dist` uses that section as the GitHub Release notes.
3. Tag the merge commit: `git tag v0.1.0`.
4. `git push origin v0.1.0`.

The tag triggers `release.yml`, which:

1. Runs the CI gates in
   [`.github/workflows/release-checks.yml`](../.github/workflows/release-checks.yml):
   `fmt`, `clippy`, `test`, `cargo test --doc`, `cargo doc --no-deps`, 85%
   line coverage, `cargo audit` and `cargo deny check`.
2. Builds each target on a native GitHub runner that dist picks, so there is
   no cross-compiling. TLS uses `reqwest`'s `rustls` feature, so no OpenSSL is
   needed; it pulls in `aws-lc-rs`, which needs a C toolchain (the runners
   have one).
3. Uploads tarballs, `sha256` checksums, and the generated
   `rs-nightshift-installer.sh` to a GitHub Release.

Nothing is published to crates.io. See
[docs/decisions.md](decisions.md) for the rationale.

## Edit the release workflow

After editing `dist-workspace.toml`, regenerate the workflow:

```text
dist init --yes   # or: dist generate
```

Regenerating drops the hand-edited `permissions` in `release.yml` (dist has
no setting for them; `allow-dirty = ["ci"]` lets `dist plan` accept the
edit). Put them back before you commit: `contents: read` for the workflow,
and `contents: write` only on the `host` job that creates the release.

Dry-run locally to verify the build:

```text
dist build --artifacts=local --target=$(rustc -vV | sed -n 's/host: //p')
```

## Action pins

Generated actions in `release.yml` are pinned to commit SHAs via
`[dist.github-action-commits]` in `dist-workspace.toml`. Verify them with:

```text
scripts/check-action-pins.sh
```

## CI drift detection

`tests/workflow_consistency.rs` asserts that `release-checks.yml` runs a
superset of the quality gates in `ci.yml`. If you add a gate to `ci.yml`, you
must also add it to `release-checks.yml` (and to `REQUIRED_GATES` in the test)
or the drift test will fail.
